# Bargain Vape — website

A static site for **bargainalternatives.com**. Wholesale-focused: it shows the
product line to retail buyers and collects inquiries. No e-commerce.

```
index.html          Home
products.html       The three display boxes and nine flavors (sleeve front/back + 10-ct box)
about.html          Brand story and how ordering works
contact.html        Wholesale inquiry form
thank-you.html      Shown after a submit when JavaScript is off
coas.html           Certificates of Analysis  ─┐
terms.html          Terms of Service           │
privacy.html        Privacy Policy             ├─ generated by scripts/build-pages.py
accessibility.html  Accessibility statement   ─┘
css/style.css       All styling
js/main.js          Age gate, navigation, animations, form
assets/img/         Optimized web images
assets/video/       Hero background video
scripts/            Build scripts (not part of the website)
```

Everything is plain HTML/CSS/JS. No build step, no framework, no server code.
Open `index.html` in a browser and it works.

## 1. Before it goes live

These are the only things that genuinely need attention.

### The inquiry form — Netlify Forms

The form is already wired for **Netlify Forms**. There is no key to paste and no
third-party account: deploy the site to Netlify and it starts working.

**What happens on deploy.** Netlify scans the published HTML for forms marked
`data-netlify="true"` and registers this one under the name
`wholesale-inquiry`. Submissions then collect under **Site configuration →
Forms** in your Netlify dashboard.

> ### ⚠️ Turn on form detection first — it is OFF by default
>
> Netlify disables form detection for new sites. Until it is switched on, the
> form posts and gets a **404**, and the site falls back to opening the
> visitor's email app. That is the single most common reason a Netlify form
> "does not work".
>
> 1. **Site configuration → Forms → Form detection → Enable.**
> 2. **Redeploy.** Enabling it does not scan the site you already uploaded — the
>    scan only runs at deploy time, so you must push a new deploy afterwards.
> 3. Reload the Forms page; `wholesale-inquiry` should now be listed.
> 4. Send yourself a test submission and confirm it appears.

**Turn on email notifications** — otherwise submissions sit in the dashboard and
nobody is told. In Netlify: *Site configuration → Forms → Form notifications →
Add notification → Email notification*, and point it at your real address. Do
this straight after the first deploy.

**The free tier allows 100 submissions per month.** Past that Netlify stops
accepting them until you upgrade, so keep an eye on the dashboard if inquiries
pick up.

**It only works on Netlify.** Opening `contact.html` locally, or hosting it
anywhere else, cannot record submissions — Netlify's servers do that work. In
that case the form falls back to opening the visitor's email client with the
inquiry pre-filled, so nothing is lost either way. This is also why submitting
from a local preview shows the "could not send that from here" message; that is
expected, not a bug.

**Do not break detection.** Three things must stay exactly as they are in
`contact.html` or Netlify will silently stop seeing the form:

1. `name="wholesale-inquiry"` and `data-netlify="true"` on the `<form>` tag.
2. The hidden `<input name="form-name" value="wholesale-inquiry">` — this is
   required because JavaScript submits the form, and its value must match the
   form's `name`.
3. Every field keeps its `name=""`. Those names become the column headings in
   the dashboard, so if you rename one, past submissions keep the old heading.

After a successful submit, visitors with JavaScript see an inline confirmation
without leaving the page. Visitors without JavaScript are redirected to
`thank-you.html`.

### The email address

`sales@bargainalternatives.com` is a placeholder. Use find-and-replace across
**all nine** `.html` files to change it — it appears twice on most pages and
five times on `contact.html`, one of which is the `data-fallback-email="..."`
attribute on the form tag. Replacing every occurrence covers them all.

### Legal pages

`terms.html`, `privacy.html` and `accessibility.html` are **drafts written as a
starting point, not legal advice**. Each carries a visible orange notice saying
so. Have your attorney review them, then delete that notice — search the HTML
for `legal__note`.

Two things in them need your input before review:

- **Governing state.** `terms.html` currently names Florida. Change it if that
  is wrong, and ask counsel whether you want an arbitration or venue clause.
- **The "last updated" date.** Set in `scripts/build-pages.py` as `EFFECTIVE`.

These pages (plus `coas.html`) are generated from the shared site shell so their nav and
footer never drift from the rest of the site. If you edit the shell (nav, footer,
age gate), regenerate them:

```bash
python scripts/build-pages.py
```

Edit the wording inside that script, not the HTML files, or your changes will be
overwritten the next time it runs.

### Legal review

Search the HTML for `LEGAL REVIEW` — the age-gate wording and the footer
disclaimer are standard placeholder language. Have your attorney confirm both,
and check state-by-state rules for everywhere you ship, before launch.

### Copy flagged as draft

Search for `EDIT:` in the HTML. Two things are written as a solid starting
point but are my words, not yours:

- **Flavor tasting notes** (`products.html`) — adjust to your actual profiles.
- **The brand story** (`about.html`) — the founding details are generic. Your
  packaging says Landis, NC, so nothing claims a Miami origin, but the story of
  *why* you started is worth putting in your own words.

Also confirm the pen specs on the home page (charge port, battery) — those are
marked with an `EDIT:` comment.

### A note on price

`$19.99` appears as *"printed on the box"* only, which is what the packaging
shows. The site deliberately makes **no claim** about margin, retail strategy,
or what a shop should charge — that is yours to decide and quote per customer.

## 2. Making edits after launch

There is no admin login — this is a static site, which is why it loads fast and
costs almost nothing to host. Edits are made in the files, then re-uploaded.

**To change text:** open the `.html` file in any plain-text editor (Notepad++,
VS Code, even Notepad), find the words, type over them, save. The files are
commented with section banners like `<!-- ==== CASE ONE ==== -->` so they are
easy to navigate.

**To change a color:** open `css/style.css`. Every color is defined once at the
very top under `:root`. Change it there and it updates site-wide.

**To swap a product photo:** drop the new shot into the `Bargain Vape` folder
using the same filename, then re-run the image script (section 5). It re-crops
and re-centres automatically. Failing that, replace the file in
`assets/img/products/` directly and update the `width=""`/`height=""` on that
`<img>` tag if the proportions differ.

**Product photos:** on the products page, every flavour photo is clickable and
cycles through three views of that flavour:

| Tap | Shows | File |
|-----|-------|------|
| 1st | Sleeve, front | `<flavor>.webp` |
| 2nd | Sleeve, back (compliance panel) | `<flavor>-back.webp` |
| 3rd | The 10-count retail box | `<flavor>-box.webp` |

Each display box additionally shows its own front and back side by side at the
top of its section.

### The COAs page

`coas.html` lists all nine flavours, each linking to its Certificate of Analysis
PDF on Google Drive. The links are defined in `scripts/build-pages.py` under
`COAS` — replace the file id (the long string between `/d/` and `/view` in a
Drive link) and re-run the script.

⚠️ **Each Drive file must be shared as "Anyone with the link — Viewer."** If a
file is left restricted, retailers get a Google permission screen instead of the
PDF, and you will not know it is happening. Test them by opening the live page
in a private/incognito window where you are not signed in to your Google
account.

Links open in a new tab so a buyer does not lose their place on the site.

### Cache busting

`css/style.css` and `js/main.js` are linked with a `?v=` number in every HTML
file. **If you edit the CSS or JavaScript, increase that number** (e.g. `?v=2`
→ `?v=3`) in all nine HTML files, or returning visitors will keep seeing the old
version from their browser cache. Editing text or images needs no such change.

### The hero video

`assets/video/hero.mp4` plays muted, looping, behind the home page headline.
`assets/img/hero/hero.webp` is its poster — it paints instantly, and the video
fades in over it once enough has downloaded. The video is deliberately skipped
(poster only) for visitors on data-saver, a 2G connection, or with "reduce
motion" enabled, so nobody is charged for a decoration they did not ask for.

To replace it, drop the new file in and run:

```bash
python scripts/faststart.py "path/to/new-video.mp4" assets/video/hero.mp4
```

That script moves the MP4's `moov` atom to the front of the file if it is not
already there. Without it a browser must download the entire video before it can
show a single frame. It is a lossless byte-shuffle — it does not re-encode or
change quality — and it is safe to run on a file that is already correct.

Keep the video short (about 8 seconds), silent, and ideally under ~5MB. It is
currently 3.3MB at 720p, which is a good size for a background hero.

**If you would rather not touch code:** send me the changes and I will make them
and redeploy.

## 3. Hosting and redeploying

**Netlify (recommended, free)**

1. Go to https://app.netlify.com/drop
2. Drag the whole `bargain-vape-site` folder onto the page
3. It goes live in seconds on a temporary URL
4. Site settings → Domain management → add `bargainalternatives.com`

To update later: drag the folder onto the same site's *Deploys* tab. Live in
seconds. Netlify keeps every previous version, so you can roll back with one
click if something breaks.

Once the first deploy finishes, go to **Site configuration → Forms** and confirm
`wholesale-inquiry` is listed, then add an email notification (see the form
section above). If the form is not listed, the deploy did not include
`contact.html` — check you dragged the whole folder.

**Any traditional web host (GoDaddy, Bluehost, Hostinger…)**

Upload the contents of `bargain-vape-site` to `public_html` over FTP. Upload
changed files again to update.

⚠️ **The inquiry form will not record submissions anywhere except Netlify.** On
another host it falls back to opening the visitor's email app, which works but
depends on them having mail set up. If you host elsewhere, switch the form to
that host's handler or a service like Formspree.

Whatever you pick, put it behind **HTTPS** — every host above does this free.

## 4. What is already handled

- **Responsive** — verified at 320, 375, 768, 820, 1280 and 1440px wide.
- **Age gate** — 21+ confirmation on first visit, remembered for the session.
- **Accessibility** — keyboard navigable, screen-reader labelled, all tap
  targets ≥44px, text contrast passes WCAG AA (body text is 18:1).
- **Reduced motion** — animation is disabled automatically for visitors whose
  device requests it.
- **Resilient** — if the animation library fails to load, every page still
  renders completely. Content is never hidden behind JavaScript.
- **SEO basics** — unique titles/descriptions, canonical URLs, Open Graph tags
  so links preview properly when shared.
- **Fast** — roughly 460KB of images across the entire site; CSS and JS
  together are under 55KB.

## 5. Regenerating images (optional)

Only needed if the source photography changes. Requires Python + Pillow
(`pip install pillow`):

```bash
python scripts/build-assets.py
```

It reads from the `Bargain Vape` folder next to this one and rewrites everything
in `assets/img/`. It crops each product to a consistent frame, keeps the white
studio background, and generates the favicons. If any image's proportions
change, update the matching `width=""`/`height=""` in the HTML.
